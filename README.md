# Techno Campgain

**سامانه طراحی و مدیریت کمپین‌های فروش توسن تکنو** — اپلیکیشن وب پیش‌رونده (PWA)، فارسی و راست‌به‌چپ، موبایل‌محور.

> ⚠️ **این نسخه پایلوت است.** داده‌ها فقط در مرورگر همین دستگاه ذخیره می‌شوند (localStorage)، هم‌گام‌سازی چنددستگاهی وجود ندارد و انتخاب «پنل مدیریت/کارگزار» **ورود امن نیست**. برای استفاده‌ی عملیاتی، باید بک‌اند واقعی وصل شود (بخش «مسیر بک‌اند»).

## امکانات
- چند کمپین مستقل؛ پلکان سطح‌ها با افزودن، حذف، تغییر نام و جابه‌جایی (آخرین سطح بدون سقف؛ نام‌های پیشنهادی برنزی/نقره‌ای/طلایی/پلاتینیوم).
- **همه‌ی فیلدهای عددی خالی شروع می‌شوند** (بودجه، حدنصاب، نرخ، تعداد فروش فرضی)، عدد منفی/نامعتبر را نمی‌پذیرند و جداکننده‌ی هزارگان دارند.
- موتور پاداش: مجموع = Σ(دستگاه‌های هر بازه × نرخ همان بازه)؛ هر دستگاه فقط در یک بازه، بازه‌های پایین‌تر دوباره قیمت‌گذاری نمی‌شوند، نرخ آخرین سطح برای دستگاه‌های بعدی ادامه دارد.
- فروش معتبر و در انتظار جدا هستند؛ پاداش قابل پرداخت، در حال تکمیل، پرداخت‌شده و مانده‌ی بودجه جدا نمایش داده می‌شود؛ پرداخت مضاعف ممکن نیست.
- «خط جاری فروش» با ۵ نوع پیام از داده‌ی واقعی، یکسان در پنل مدیریت و کارگزار؛ با `prefers-reduced-motion` به فهرست ایستا تبدیل می‌شود.
- پنل مدیریت: داشبورد، کمپین‌ها، کارگزاران (فیلتر، صفحه‌ی جزئیات)، فروش (تشخیص سریال تکراری، تأیید/رد)، پرداخت‌ها، گزارش CSV و سابقه‌ی تغییرات.
- پنل کارگزار: سه پاسخ ساده (سطح من؟ تا پاداش بعدی؟ تا سطح بعدی؟) و بدون دسترسی به بودجه یا داده‌ی سایر کارگزاران.
- PWA: manifest، service worker نسخه‌دار با پیام به‌روزرسانی، پوسته‌ی آفلاین، مسیرهای نسبی سازگار با GitHub Pages.

## اجرا
```bash
npm install
npm run build        # خروجی در docs/
npm start            # http://localhost:4173  (یا BASE=/techno-campgain/ npm start برای شبیه‌سازی GitHub Pages)
npm test             # تست‌های واحد/قرارداد (۵۵ تست)
npm run test:e2e     # تست مرورگری Playwright روی docs/
```

## انتشار روی GitHub Pages
این بسته هم در ریشه (`index.html`) و هم در `docs/` نسخه‌ی ساخته‌شده دارد؛ در Pages می‌توانید **`main` + `/ (root)`** یا **`main` + `/docs`** را انتخاب کنید. برای ساخت دوباره‌ی هر دو: `npm run build:root`.

1. محتوای این پوشه را در یک مخزن بگذارید (پوشه‌ی `docs/` که خروجی ساخته‌شده است باید commit شود).
2. در GitHub: **Settings → Pages → Build and deployment → Deploy from a branch → `main` / `/docs`**.
3. آدرس: `https://<user>.github.io/<repo>/` — همه‌ی مسیرها نسبی‌اند و نیازی به تنظیم نیست.
4. پس از هر تغییر در `src/`: `npm run build` و commit کردن `docs/`.

## معماری (UI / منطق / داده جدا)
```
src/domain   منطق خالص و تست‌پذیر: engine (پلکان و پاداش)، ticker، ledger، commands (applyCommand)، projections
src/data     Repository: localStorage، memory، HTTP (همان قرارداد)
src/ui       React 19 — بدون منطق مالی؛ فقط فراخوانی دستور و نمایش
server/      سرور مرجع (node:http) برای اثبات قرارداد — بدون احراز هویت، فقط برای توسعه
```
- هر تغییر یک **دستور** است (`applyCommand`) — اتمیک، idempotent (`idempotencyKey`) و نسخه‌دار (`expectedVersion`).
- کارگزار فقط یک مدل خواندنیِ کوچک می‌گیرد (`agentSnapshot`) که بودجه و داده‌ی دیگران را ندارد.
- هیچ رازی در کلاینت نیست.

## مسیر بک‌اند
جزئیات در [`docs-src/BACKEND.md`](docs-src/BACKEND.md). خلاصه: `httpRepository` را به‌جای `localStorageRepository` در `src/main.tsx` بگذارید و سه endpoint را پیاده کنید؛ مجموعه‌ی تست قرارداد باید بدون تغییر روی بک‌اند واقعی هم سبز شود.

## تست‌ها
- `tests/engine.test.ts`، `commands.test.ts`، `contract.test.ts`: معیارهای پذیرش (با برچسب «پذیرش N» در نام تست)، ایزوله‌سازی کارگزار، idempotency، همروندی، قفل پرداخت، سه Adapter با یک مجموعه‌ی تست.
- `tests/e2e.mjs`: اسپلش ۵ ثانیه‌ای، لوگو/عنوان، فیلدهای خالی، ساخت کمپین و پیش‌نمایش مالی، ماندگاری، سریال تکراری، یکسان بودن خط جاری در دو پنل، پنهان بودن بودجه از کارگزار، reduced-motion، manifest/SW/آفلاین زیر زیرمسیر، نبود خطای کنسول.

## محدودیت‌های شناخته‌شده
- پایلوت: بدون ورود امن، بدون هم‌گام‌سازی، داده با پاک‌کردن مرورگر از بین می‌رود (در «تنظیمات» پشتیبان‌گیری/بازیابی هست).
- قلم Yekan به‌صورت TTF همراه است.
- ساخت با esbuild انجام می‌شود (بدون Vite)؛ در صورت تمایل، مهاجرت به Vite ساده است چون ورودی `src/main.tsx` است.
